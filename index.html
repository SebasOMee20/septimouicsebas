01 · La naturaleza del disfraz

Todo cloaking se comporta distinto según quién lo mire.

Antes de detectar un engaño hay que entender cómo percibe, decide y confía una persona — y cómo un sistema automatizado puede aprender a notar lo que un usuario distraído no nota.

A

Percepción y confianza

Percepción, memoria y atención explican por qué una persona no nota que un sitio cambió de contenido entre la carga inicial y una interacción — la misma señal que debe aprender a reconocer un clasificador automático.

B

Señales de comportamiento

El feedback inconsistente, los redirects silenciosos y la ausencia de confirmación delatan tanto una mala interfaz como un sitio camuflado ante un escáner.

C

Apariencia familiar

Un patrón visual familiar genera confianza — y es exactamente lo que un sitio fraudulento imita para parecer legítimo ante quien lo visita.

02 · Técnicas reales de cloaking

Cuatro formas en que un sitio se disfraza.

Estos son los métodos más comunes que usan los sitios fraudulentos para mostrarle una cara distinta a un sistema de seguridad que a una persona real.

Cloaking por User-Agent

El servidor lee el identificador del navegador antes de responder. Si detecta un rastreador (Googlebot, escáneres de seguridad), entrega una versión limpia del sitio. A cualquier otro visitante le muestra el contenido real.

  • Detecta el identificador del navegador antes de responder.
  • La versión "limpia" nunca llega a un análisis automático.
  • Se descubre comparando respuestas con distintos User-Agent.

Cloaking por dirección IP

El sitio mantiene una lista de rangos de IP conocidos de empresas de seguridad y buscadores. A esas IPs les responde con contenido inofensivo; a cualquier otra, con el contenido fraudulento.

  • Requiere mantener listas actualizadas de IPs de escáneres.
  • Más costoso de mantener, pero más difícil de evadir por el visitante.
  • Se descubre repitiendo la petición desde IPs distintas.

Cloaking por retraso

La página carga limpia al inicio y solo después de varios segundos ejecuta una redirección o inyecta contenido malicioso — el tiempo justo para pasar un análisis automático rápido, pero no para engañar a alguien que se queda navegando.

  • Explota el límite de tiempo de los escáneres automáticos.
  • El contenido inicial y el final nunca coinciden.
  • Se descubre observando el sitio más allá del primer segundo.

Cloaking por referencia de búsqueda

El sitio revisa de dónde viene la visita. Si detecta que la persona llegó haciendo clic en un resultado de búsqueda, muestra la página fraudulenta; si entra escribiendo la URL directamente, muestra una versión inofensiva.

  • Explota la confianza que genera aparecer en resultados de búsqueda.
  • El mismo enlace se comporta distinto según cómo se accede a él.
  • Se descubre visitando el sitio con y sin referencia de búsqueda.

03 · Entrenamiento del modelo

Ninguna detección funciona sin un modelo bien entrenado.

El sistema debe reducir falsos positivos, ofrecer señales claras y explicar cada resultado que entrega.

Concepto Aplicación en el sistema
Memoria Reconocer patrones de estafa ya vistos, sin que el usuario tenga que recordarlos activamente en cada sitio nuevo.
Carga cognitiva Los estafadores explotan la sobrecarga (urgencia, miedo) para reducir el análisis crítico de la víctima.
Retroalimentación La ausencia de confirmación clara en un flujo es en sí misma una señal de alerta que el sistema debe capturar.
Errores Mensajes de error o éxito falsificados se usan para manipular la percepción de seguridad del usuario.
Consistencia El cloaking es, literalmente, la explotación de la inconsistencia entre lo que ve un escáner y lo que ve una persona.
04 · Herramientas del sistema

Cómo se compara y clasifica cada sitio.

El modelo aporta valor solo cuando compara comportamiento real: lo que ve un rastreador automático frente a lo que ve una persona.

Comparación dual de contenido

El sistema solicita la misma página simulando un escáner y simulando un navegador humano, y compara ambas respuestas usando embeddings SBERT para medir qué tan distintas son.

Clasificador de intención

Random Forest y XGBoost aprenden de un dataset realista de sitios camuflados y legítimos para decidir, con evidencia, si una página está ocultando su verdadera cara.

05 · Metodología del proyecto

Del primer sprint al sistema en producción.

El desarrollo del Sistema AntiCloaking sigue una metodología Scrum adaptada a 9 sprints, desde el dataset hasta el frontend funcional.

  1. Definición del MVP
    Alcance: motor de Machine Learning, API y frontend básico.
  2. Construcción del dataset
    Casos realistas de cloaking y sitios legítimos, etiquetados para entrenamiento.
  3. Modelado y comparación
    Embeddings SBERT y clasificadores Random Forest / XGBoost.
  4. API y roadmap de desarrollo
    FastAPI expone los resultados; el roadmap se organiza por fases.
  5. Frontend y validación
    Interfaz de consulta y pruebas sobre el sistema completo.
